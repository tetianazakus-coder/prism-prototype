Where we start

The live site is a Next.js 16 app (React 19, TypeScript, Tailwind 4) in apps/lender-prism/frontend/, with Rails behind it as a JSON API. The prototype is hand-written HTML, CSS and JavaScript, so the work is a port into React components, not a file copy.

Serving the prototype's HTML from frontend/public/ would not work: those pages would have no session, no tracking and no environment values, and /assets, /images and /fonts are proxied to Rails.

Phase 1: foundation (first PR)

The first PR carries no page content. It sets the pattern every later page follows, so it is the one to review most closely.

Tanya

  • Marketing layout in src/app/(landing)/layout.tsx: the prototype's stylesheets in their load order, fonts through next/font, and motion switched off when the visitor asks for reduced motion.
  • New header and footer in place of Navbar-var.tsx and footer8.tsx on marketing pages. They keep what the live header does: a signed-in visitor sees Dashboard, and nav_cta_clicked still fires.
  • Images in frontend/public/assets-landing/editorial/. About 22 of the prototype's 53 image files are unused and stay behind.
  • The behaviour in site.js and motion.js as client components. The prototype's hand-written ?v= cache keys go, because Next fingerprints assets.

Ask Chris

  • Review the first PR before any page is built on it.

Tanya, on every page
